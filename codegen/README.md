# Protocol Code Generator

A code generation tool that ensures consistency between the Rust `protocol` library and Python `plugin_host` library by treating Rust as the source of truth.

## Overview

This tool addresses the critical issue of maintaining consistency between Rust and Python protocol implementations. Instead of manually keeping both libraries in sync, this code generator parses the Rust protocol library and automatically generates equivalent Python code.

## Architecture

```text
┌─────────────────┐    Parse AST    ┌─────────────────┐     Generate     ┌─────────────────┐
│   Rust Protocol │ ──────────────► │  Code Generator │  ─────────────►  │  Python Types   │
│     Library     │                 │                 │                  │                 │
└─────────────────┘                 └─────────────────┘                  └─────────────────┘
        │                                     │                                  │
        │                                     │                                  │
   Source of Truth                     Validation Tool                     Generated Code
```

## Features

- **AST Parsing**: Directly parses Rust source code using `syn` to extract definitions
- **Template Generation**: Uses Askama templates for clean Python code generation
- **Type Mapping**: Automatically maps Rust types to Python equivalents
- **Documentation Preservation**: Carries over documentation comments from Rust

## Usage

### Generate Python Code

```bash
# Generate Python types from Rust protocol library
cargo run --bin generate-python

# Generate to a specific output directory
cargo run --bin generate-python -- --output-dir /path/to/output

# Specify custom protocol source path
cargo run --bin generate-python -- --protocol-path /path/to/protocol/src
```


## Generated Content

The tool generates the following Python code:

### Constants
- `MESSAGE_MAGIC` (0xDEAD)
- `DEFAULT_PACKET_SIZE` (256)
- `MAX_NAME_SIZE` (30)  
- `MESSAGE_HEADER_SIZE`, `MESSAGE_MAGIC_BYTES`, etc.

### Enums
- `MessageTypeId` with all host commands (0x01-0x7F) and plugin responses (0x80-0xFF)
- `BLEProperties` (READ, WRITE, NOTIFY, etc.)
- `BluetoothAddressType` (Public, Random, etc.)

### Message Structures
- All host command structs (e.g., `HostCommandConfigurePeripheral`)
- All plugin response structs (e.g., `PluginServiceInfoResponse`)
- Proper Python type annotations based on Rust types

### Type Mappings
- `MESSAGE_TYPE_MAP`: Maps Python classes to MessageTypeId enum values
- `TYPE_ID_TO_MESSAGE_TYPE`: Reverse mapping for dispatch

## Type Conversion

The tool automatically converts Rust types to Python equivalents:

| Rust Type | Python Type |
|-----------|-------------|
| `u8` | `attrs2bin.U8` |
| `u16`, `u32`, `u64` | `int` |
| `f32`, `f64` | `float` |
| `bool` | `bool` |
| `String`, `&str` | `str` |
| `Uuid` | `str` |
| `Vec<u8>` | `List[attrs2bin.U8]` |
| `Vec<T>`, `heapless::Vec<T>` (T ≠ u8) | `List[T]` |
| `Option<T>` | `Optional[T]` |
| `heapless::String<N>` | `str` |

**Note**: `u8` and `Vec<u8>` are mapped to `attrs2bin.U8` and `List[attrs2bin.U8]` respectively to support proper binary serialization through the attrs2bin library. Other integer types (`u16`, `u32`, `u64`) are mapped to Python's `int` type.

## Implementation Details

### AST Parsing

The tool uses the `syn` crate to parse Rust source files:

1. **Constants**: Extracts `pub const` declarations with their values and documentation
2. **Enums**: Extracts enum definitions with discriminant values and variants
3. **Structs**: Extracts struct definitions with field types and derives

### Template System

Uses Askama templates for clean separation between parsing logic and output generation:

- Template-friendly data structures avoid Option types that cause template issues
- Comprehensive documentation is preserved and formatted for Python
- Type mappings are generated automatically


## Dependencies

- `syn`: Rust AST parsing with full feature support
- `quote`: Code generation utilities
- `askama`: Template engine for Python generation
- `clap`: Command-line argument parsing
- `anyhow`: Error handling
- `chrono`: Timestamps for generation reports

## Example Output

```python
# GENERATED CODE - DO NOT EDIT MANUALLY
# This file is automatically generated from the Rust protocol library

import attrs2bin
from typing import List, Optional

# Constants
MESSAGE_MAGIC = 0xDEAD
DEFAULT_PACKET_SIZE = 256
MAX_NAME_SIZE = 30

# Enums
class MessageTypeId(Enum):
    HostCommandConfigurePeripheral = 0x01
    HostCommandConfigureService = 0x02
    # ... more variants
    PluginData = 0x80
    PluginConfigurationError = 0x81

# Message structures
@attr.s(auto_attribs=True)
class HostCommandConfigurePeripheral:
    name: str
    uuid: str
    max_connections: Optional[attrs2bin.U8]

@attr.s(auto_attribs=True)
class PluginData:
    connection_id: int
    characteristic_uuid: str
    data: List[attrs2bin.U8]  # Vec<u8> maps to List[attrs2bin.U8]
    timestamp: int
```

## Limitations

- Currently focuses on basic type extraction (constants, enums, structs)
- Complex generic types may need manual mapping
- Template formatting might need adjustment for specific Python styles
- Doesn't generate serialization/deserialization logic (relies on attrs2bin)

## Troubleshooting

### Template Compilation Errors

If you see template compilation errors, ensure:
- Template data structures don't use `Option<T>` (use empty strings instead)
- Template syntax is valid Askama syntax
- All referenced fields exist in the template data structures

### Parsing Errors

If AST parsing fails:
- Check that the protocol source files have valid Rust syntax
- Ensure all dependencies are available for the protocol crate
- Verify the source paths are correct

### Type Mapping Issues

If generated Python types are incorrect:
- Check the `rust_type_to_python` function in `src/lib.rs`
- Add new type mappings as needed
- Consider complex generic types that might need special handling
